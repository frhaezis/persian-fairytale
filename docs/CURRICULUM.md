# persian fairytale. V2 — карта учебной программы

Версия 2 содержит 40 миссий в четырёх актах, 168 содержательных шагов объяснения и 128 записей карты тем. Это разные единицы: запись темы не означает отдельный уровень или подтверждённое освоение. Встроенный редактор предоставляет 20 отдельных упражнений Python/PyTorch; 16 из них напрямую входят в маршрут миссий, остальные доступны для самостоятельной практики.

Теоретический путь идёт от классического ML к PyTorch, Transformers, RAG, агентам, адаптации, alignment и production. Практика Windows отличается от мобильного курса: здесь действительно выполняются PyTorch-код, обучение, оценка и контролируемые сравнения; можно отдельно подключить собственный локальный HTTP runtime. Большая языковая модель для прохождения не нужна.

## Как устроена каждая миссия

1. Короткая сцена задаёт цель; технические требования написаны обычным языком.
2. Предпосылки напоминают нужные понятия. Затем идут самостоятельные смысловые шаги с примерами.
3. Разобранный пример показывает метод до задания, обычно на других входах.
4. «Связь с практикой» объясняет, какие действия нужны именно в текущем устройстве или упражнении. Для кода дополнительно открыт отдельный учебник APIs, функций, методов и формата результата.
5. Проверка и перенос используют уже объяснённые факты. Разбор ошибок доступен рядом с практикой, а свободный ответ сопровождается образцом для самопроверки.

В `data/curriculum.json` у каждого проверяемого действия, вопроса, карточки и вопроса карты тем есть `teaching.assessmentMap` со ссылками на объясняющие шаги. Это трассируемость учебного содержания, а не автоматическое доказательство понимания человеком.

## Темп и повторение

1200 минут — сохранённый ориентир авторского плана, а не измеренная длительность и не обещание освоить профессию за 20 часов. Подробное чтение, код, ошибки и повторение могут занять больше. Резерв 240 минут также является планом. Игра не требует ждать для получения прогресса; таймеры алгоритмических задач предназначены для отдельной репетиции после изучения.

Состояние «решено с подсказкой» не равно независимому решению. Успешный пример не доказывает перенос на произвольные данные. Сохранение V2 отделяет новый маршрут от прежнего прогресса; для возврата к материалу доступны объяснения, примеры и практика. Скорость автоматического прохождения проверяет связность интерфейса, а не темп обучения человека.

## Реальные вычисления и границы опытов

- m11–m19: CPU tensors, формы, autograd, nn.Module, losses, optimizer, train/eval/no_grad, обучение линейной модели и Dropout. В m19 три одинаковые по устройству сети с p=0/0.2/0.8 обучаются из одинаковых начальных весов на одном разбиении. Кривые — реальные измерения, и улучшение от Dropout не предрешено.
- m31: настоящий Python-контур вызывает детерминированный инструмент и обрабатывает его реальный результат. LLM в этой обязательной задаче нет; такой режим явно назван test double.
- m32: при желании пользователь самостоятельно запускает совместимый runtime и проверяет localhost API. Ограниченный агент действительно получает решения по HTTP, проверяет JSON-действия, вызывает учебные tools и передаёт наблюдения обратно. Бюджет 1–4 ответа модели; ошибки и stop завершают контур. Имя весов и фактическая правильность цели не удостоверяются успешным HTTP обменом.
- LoRA, QLoRA, RLHF, DPO, distillation и vLLM рассматриваются как механизмы и исследовательские решения. Игра не изображает карточное действие как выполненное обучение большой модели или запущенный production-кластер.
